## 关键 Bug 修复（15:51）
**问题：** 用户报告「点开始无法开始游戏」。
**根因：** `.overlay` CSS 写的是 `pointer-events: auto`（无条件）。开始遮罩 `.show` 被移除后只是 opacity→0 淡出，但 div 仍占据整个 stage 且 z-index:50，**持续拦截所有鼠标点击**。结果是 startBtn 能点（按钮在遮罩内部）→ gameStarted 翻成 true → 计时器确实在跑 → 但用户点水面 / 鱼 / 按钮全无响应，看起来"没开始"。
**修复：** 改为 `pointer-events: none` 默认 + `.overlay.show { pointer-events: auto; }`，让隐藏的遮罩完全 pass-through。
**教训：** 半透明遮罩一定要配套管理 `pointer-events`，不能只靠 opacity 隐藏。`opacity:0` 不等于「不存在」。

## 关键 Bug 修复 · 真正根因（16:01）
**复测：** 修复 pointer-events 后用户仍反馈「无法开始」。用 playwright + Edge 实测抓到真凶。
**真正根因（TDZ ReferenceError）：** `resize()` 在 IIFE 顶部的第 375 行**立即调用**，而它内部调用 `initPebbles()` / `initGrass()`。这两个函数是 `function` 声明会被 hoist，所以 `typeof initPebbles === 'function'` 守卫能通过；但它们体内引用的 `const pebbles = []` / `const grass = []` **还没执行到（temporal dead zone）**。于是抛 `ReferenceError: Cannot access 'pebbles' before initialization`，整个 IIFE 在 **375 行直接中断** —— **后续所有 `addEventListener`（含 startBtn）根本没绑定**，这就是点开始完全没反应的真正原因。
**修复：** 把 `const grass = []` / `const pebbles = []` 上移到 `resize()` 首次调用之前（文件顶部 W/H 声明后），并删掉原位置重复的 `const` 声明。
**验证：** 实测点击开始后 `.show` 移除、`pointer-events:none`、opacity:0，计时器 60→58 正常倒数，空格抛竿计数+1、状态正常，**0 页面错误**。
**推广教训：** `function` 声明被 hoist 不代表它的**依赖变量**也初始化了。`typeof fn === 'function'` 守卫会骗过直觉 —— 它保证函数存在，但**不保证函数体引用的 TDZ 变量已可用**。凡是在启动早期（如 resize）就调用、且函数体引用上层 `const` 的，必须把这些 `const` 提前声明或在真正初始化后再触发调用。
